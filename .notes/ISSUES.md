# Open issues
- The release build (`build-release`, `-O3 -DNDEBUG`) does not repeat itself while the debug build does. `rtx release bench --views=one-cell-walk --hashes=a; rtx release bench ... --against=a` on one binary differed on 288 of 1200 frames from frame 913 with every scene and constants column identical, and `rtx release shot --views=dagoth-ur-caldera --against=<its own earlier shot>` differed by 43 of 255 on 29% of the pixels; `rtx debug repeat --pairs=10` on the same tree was identical ten times. Measured 2026-09-19 after the sky-state change and against the pre-change stash alike. Stills too: `rtx release shot` of `balmora-storm-night`, `dagoth-ur-caldera`, `island-crossing`, `island-crossing-end`, `one-cell-walk` and `sadrith-mora` against the same binary's own earlier pictures differed on all six (the storm by 238 of 255 on 8% of the pixels, the rest by 12 to 23 on 15% to 30%), while `rtx debug shot` of `island-crossing` and `one-cell-walk` against itself was byte-identical.
- The ray tracer's cell ring has no blacklist. `RenderingManager::pagingBlacklistObject` tells `ObjectPaging` about a reference the game moved, deleted or animates, so the paging never stands it in the distance. `Rtx::CellRing` has `setReferenceEnabled` and nothing for the blacklist, so a static a script moved in a cell that later goes distant is stood by the ring at its content-file position.
- `shot --views=all --map` at its defaults (Ray Reconstruction on, exposure measured) draws `balmora-storm-night` in one of two states, a part in 19 of 255 apart on 11% of the pixels, and which state a binary draws is not a function of its code: a pure move of members out of `RtxRenderer` (`RtxWindow`, `ViewQueue`, `FrameTimer`) changed the state, and a binary draws the same state on every run. The other 45 pictures, `check`, `repeat`, and `bench --views=all --hashes --upscale=off` are the same across the same binaries. Measured 2026-09-19 in the debug flavour; a single-view `shot` of the storm is the same across those binaries too.
